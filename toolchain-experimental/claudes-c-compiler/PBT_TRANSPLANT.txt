# LCCC — World-Class Code Generation & Compiler Optimization Research Program

## 0. SUPREME OBJECTIVE

Du arbeitest als **weltklasse Compiler-Optimierungsforscher, Backend-Architekt, Microarchitecture-Experte, Performance Engineer, Compiler-Fuzzer und Systems Programmer**.

Hierum geht es, mein Repo mit LCCC: https://github.com/ms178/lccc

Dein primäres Ziel ist:

> **Erzeuge mit lccc den schnellsten, effizientesten und qualitativ hochwertigsten Maschinencode, der auf realer Hardware für reale Workloads praktisch erreichbar ist.**

**Generated-Code Performance ist das wichtigste Optimierungsziel des gesamten Projekts.**

Nicht:

* maximale GCC-Kompatibilität,
* maximale Clang-Kompatibilität,
* möglichst einfache Implementierung,
* möglichst wenige Compilerzeilen,
* theoretisch elegante IR,

sind das primäre Ziel.

Diese Eigenschaften sind wichtig, aber nachgeordnet gegenüber:

```text
GENERATED-CODE PERFORMANCE
        ↓
CODE QUALITY
        ↓
CORRECTNESS
        ↓
PORTABILITY
        ↓
COMPILE-TIME
        ↓
MEMORY USAGE
        ↓
BINARY SIZE
```

Correctness ist dabei eine **harte Nebenbedingung**:

> Ein schneller falscher Compiler ist wertlos.

---

# 2. GCC / CLANG / ICX SIND BASELINES — KEINE VORBILDER

Ein fundamentaler Grundsatz:

> **Niemals automatisch davon ausgehen, dass GCC, LLVM oder ICX den optimalen Algorithmus verwenden.**

Ihre Implementierungen sind Referenzpunkte.

Wenn GCC besser ist:

```text
Do NOT simply copy GCC.
```

Stattdessen:

1. generierten Code vergleichen,
2. Performance Counter analysieren,
3. relevante Optimierung identifizieren,
4. zugrunde liegende Ursache verstehen,
5. Literatur durchsuchen,
6. alternative Algorithmen untersuchen,
7. eigene Variante entwickeln,
8. messen.

Wenn lccc eine bessere Lösung findet:

> **Diese soll unabhängig von GCC/LLVM implementiert werden.**

## 4. Choices I agree with
### Fix the emission-order dependency, not the optimizer
A CFG-dominating GEP need not precede its consumer in physical block emission order. The immutable function-wide maps are the appropriate admission criterion for the map-aware load/store path. Disabling IV widening, LICM, MachInst, or folding globally would hide the symptom while throwing away unrelated optimization. Main now owns this production fix; this branch correctly reuses it.
### Validate ADR/ADRP fields before masking
The shared signed-21-bit helper is small, legible, and correctly separates byte displacement for ADR from page displacement for ADRP. Checking input-section bounds before forming output addresses and checking the final output field before mutation are complementary protections, not redundant checks. Propagating `Result` through all changed encoder call sites is the right direction.
### Defer page-dependent local ADRP resolution
Final section placement determines the page difference. Keeping a relocation with the symbol offset and addend is preferable to baking in a temporary section-zero assumption. Restricting that change to ADRP avoids adding unnecessary relocations everywhere.
### Use SWAR only when the register restriction requires it
The 32-/64-bit SWAR sequence is a sensible fixed-work implementation. x1 is outside the allocated caller-saved pool; W-register operations correctly discard unspecified upper argument bits. Retaining the ordinary NEON implementation avoids turning an ISA repair into an unsupported performance claim.
### Fail loudly on unsupported output
An unsupported relocation must not produce a nominally successful shared object with an unpatched instruction. The stronger diagnostics are a deliberate compatibility change, but preferable to silently incorrect output.

The new ADR decision treats hidden/protected declarations as binding constraints, while the shared emitter can export the definition as GLOBAL DEFAULT. The archived visibility reproducer already acknowledges this. A locally computed address is not proof that external symbol lookup, interposition, and GOT/PLT references honor the same contract.
**Instructions:** choose one explicit scope:
1. Properly carry and merge visibility through symbol resolution, then use the same binding decision for exports, `st_other`, GOT/PLT allocation, and relocation application; or
2. Narrow the newly supported shared ADR cases to definitions whose local binding can actually be guaranteed, diagnose the unsupported non-local cases, and leave full visibility repair as a separately tracked task.
Do not grow more independent name-only side tables in individual emitters. Do not claim that fixing one ADR admission predicate repairs ELF visibility globally.
**Acceptance:** hidden/internal symbols cannot be externally resolved; protected definitions remain exported but bind internally; default/weak interposition remains correct. Cover cross-TU input order, undefined declarations followed by definitions, and same-named local symbols. Inspect emitted ELF and execute an interposition/pointer-identity fixture against an independent linker. This is substantial enough not to implement speculatively without a compiler-capable runner.
### F3 — P2: non-preemptible does not prove section-relative
**Status:** open, source/model counterexample; **not yet an executable-level reproduction**.
Location: [new shared ADR predicate](https://github.com/ms178/lccc/blob/a3fedbc/src/backend/arm/linker/emit_shared.rs#L1214-L1233), together with [symbol resolution](https://github.com/ms178/lccc/blob/a3fedbc/src/backend/arm/linker/reloc.rs#L70-L114).
For ELF symbol index zero, binding is local and section index is UNDEF. The new range check accepts index zero when the symbol table is nonempty. The ADR predicate rejects ABS and preemptible symbols, but a local undefined symbol is neither. Resolution returns S=0.
A model with P=`0x10000`, A=0, and load bias B=`0x70000000` passes the signed displacement check. Encoding S−P causes the runtime ADR result to become B, not absolute zero. The predicate therefore fails to establish its own stated section-relative precondition.
**Instructions:** first add a minimal ELF mutation fixture targeting symbol zero, then confirm the actual linker result. Check local undefined symbols, absent/discarded section mappings, absolute targets, and normal local/section-symbol controls. Use a typed resolution result or an explicit checked section-relative resolver rather than guessing from a numeric address; address zero can be valid. Preserve NONE-relocation behavior and do not reject unrelated legitimate relocation kinds globally.
**Acceptance:** the counterexample fails with a normal diagnostic before output is committed; valid local and section-symbol ADRs still link, with independently decoded fields in all applicable modes. Only implement the behavior change after that reproducer establishes the actual path.
### F4 — P2, repaired: optimization and environment overrides could weaken gates
**Status:** fixed and pushed in `a3fedbc`. **Confidence:** directly exercised with compiler-free tests.
The new scripts relied on Python `assert` for their verdicts. Before repair, a mocked failed compiler result was rejected normally but accepted with `python -O`. The parity checker also accepted workflow-level `CCC_ARM` and `PYTHONOPTIMIZE` overrides for these newly registered programs.
**Implemented:** fail before tool invocation when assertions are disabled; pin `CCC_ARM=target/fastbuild/lccc-arm` in both mirrors and invocation contracts; reject the two environment channels at workflow/job/step scope.
**Evidence:** all **69 parity tests** pass. The two added tests replayed against the pre-fix files produce **18 expected failures**: 12 gate/variable/scope combinations and six optimized-import combinations. Fixed files pass those same cases. Normal imports remain valid. These tests never invoke a compiler.
**Retain:** both the executable preflight and environment checks. An environment allowlist alone does not protect direct developer invocations using `-O`.
### F5 — P2 coverage weakness: hosted runtime coverage remains optional
**Status:** open; this is an enforceability issue, not evidence of a wrong popcount result.
Location: [runtime selection](https://github.com/ms178/lccc/blob/a3fedbc/tests/regression/check_arm_popcount_contract.py#L32-L59) and the hosted invocation in `.github/workflows/ci.yml`.
Installing qemu-user makes execution likely on the current runner, but the invocation omits `--run`. If QEMU becomes unavailable, the script reports zero runs and may still pass its compile/structural checks. The reporting is honest; the mandatory CI contract is weaker than the provisioned runtime suggests.
**Instructions:** require `--run` on hosted CI, model hosted/local invocation differences explicitly in the parity checker, and keep an explicitly labeled compiler-only local mode if desired. Add compiler-free tests for missing QEMU and mutation tests proving that removing hosted `--run` is rejected. Keep the fresh-compiler pin introduced by F4.
**Acceptance:** missing QEMU fails the hosted gate before compilation; successful hosted output proves **10 executions** (five optimization modes × default/restricted), and cannot turn into a green compile-only run.
